# P25 keyed voice regression vectors

`crates/engine/tests/fixtures/op25-voice-keystream.txt` was generated by compiling
boatbod OP25 commit `71abcd0ead32f86f51615ea6cc8a6a4dba4c949a`'s crypto classes.
Each row is ALGID (hex), phase (1/2), and the concatenated decrypted zero voice
words (18 IMBE or AMBE words). Public test keys are incrementing bytes starting
at zero, with lengths 5/8/32; KID is 0x1234; MI is 123456789abcdef000.
These exercise cipher initialization, MI expansion, OFB/RC4 discard, LSD skips,
and the LDU boundary, rather than just encrypt/decrypt round trips.

To regenerate using an OP25 checkout at that commit (no GNU Radio required):

```sh
mkdir -p /tmp/op25-vector-stubs/gnuradio
touch /tmp/op25-vector-stubs/gnuradio/msg_queue.h
OP25_LIB=/path/to/op25/op25/gr-op25_repeater/lib
c++ -std=c++17 -include cstdint -I/tmp/op25-vector-stubs -I"$OP25_LIB" \
  tools/p25-crypto/op25-vectors.cc \
  "$OP25_LIB"/op25_crypt_{algs,adp,des,aes}.cc -o /tmp/op25-vectors
/tmp/op25-vectors > crates/engine/tests/fixtures/op25-voice-keystream.txt
cargo test -p scannerd-engine crypto::tests::p25_matches
```

The harness flushes stdout and exits without invoking OP25's manager destructor:
that revision erases an iterator and subsequently reuses it during destruction.
No upstream cipher implementation is included in uSDR.

Coverage does not certify RF acquisition or intelligibility from a particular
radio. Replaying an authorized capture through both receivers remains the final
interoperability check. Missing keys and unknown encryption state remain muted;
a matching key address means a key was applied, not that it was authenticated.
