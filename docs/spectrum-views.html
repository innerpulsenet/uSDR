Five other ways to see the band

AetherSDR's 3D mode stacks recent FFT frames into a perspective surface and leaves the waterfall flat underneath. Your mockup goes further and turns the whole history into terrain. Both are here, with three quieter options between them and today's panafall for reference. They all run on one band, in the app's own palettes, so you can switch and judge.

SIMULATED Every signal on this page is invented: CW, FT8 and FT4 in their slots, an NCDXF beacon cycle, RTTY, PSK31 and two SSB contacts. Nothing here is a recording.

Spectrum · AetherSDR's approach

Ridges

The last few seconds of frames stand behind the live trace in perspective. Each one is filled to its own floor, so it hides what's behind it. A keyed carrier becomes a dotted ridge, and an FT8 slot rises and falls as a block. The waterfall underneath stays flat and exact.

Build
The rows are already in wf_q. Draw R of them back to front as one egui::Mesh (a quad strip per trace, colored from the LUT), then the live trace on top. About 60 × 512 quads.
Tuning
Unchanged. The front trace keeps today's x scale.
Weak spot
A strong ridge can hide weak ones behind it. Only the front trace sits on the dB scale.
Spectrum · real-time analyzer

Persistence

The panadapter becomes a heat map of where the trace has been over the last second. A steady carrier is a hard line and noise is a soft band. A 20 ms CW element still burns in, and you see the full spread of an SSB voice instead of one instant of it.

Build
A 1024 × 256 hit buffer in Panafall::push, decayed each frame, uploaded and colored the same way the waterfall texture is.
Tuning
Unchanged.
Weak spot
Slower to read at a glance. Its memory is the decay time, not the waterfall's five minutes.
Waterfall · lit

Relief

Every pixel stays where it is today, but each cell is shaded by its slope against its neighbors in frequency and time, like a relief map. Carriers stand off the noise, and keying edges and slot boundaries catch the light. It's the 3D feel with no geometry change.

Build
One multiply per cell in color_row, using the row below it, which is already in wf_q. CPU only.
Tuning
Unchanged.
Weak spot
Brightness carries slope as well as level, so a cell no longer reads as one exact level. That's what the strength slider is for.
Scene · your mockup

Terrain

The whole history becomes one lit surface: frequency across, time into the distance, level as both height and color. The receiver's passband is a glass slab through time. Orbit it with a drag.

Build
An egui_wgpu paint callback with its own pipeline. wf_q is already u16, so it uploads as an R16 texture, and a vertex shader displaces a 512 × 256 grid. Peak-of-two per column keeps one-bin carriers.
Tuning
Needs a ray pick onto the front edge, or a flat strip to click.
Weak spot
Perspective makes frequency unreadable away from the front, and near peaks hide far ones. It uses the most GPU, which the Windows PC's GPU needs checking for.
Scene · 2.5D

Tilted

The waterfall is laid back like a floor, with the live spectrum standing as a curtain on its front edge. It reads as depth without hiding anything behind peaks.

Build
The terrain pipeline with zero height plus one curtain strip. Nearly free once Terrain exists.
Tuning
On the curtain, which is to scale.
Weak spot
Time is compressed with distance, and it shows less than Split in the same space. It's mostly a look.

What I'd build

  1. Ridges first. It gives the most depth for the least risk. It's the same direction AetherSDR took (a stacked-trace surface added in v26.7.1, a depth slider in v26.8.2). It leaves the waterfall pixel-exact, which is your stated priority, and click-to-tune doesn't change.
  2. Persistence second. This is the one that shows you something new rather than something prettier: intermittent and bursty signals under a busy band. It's cheap because it reuses the waterfall's texture and color path.
  3. Relief third. Half a day of work, and it makes the flat waterfall look dimensional while keeping every pixel where it is today. Default it to off, with a strength slider.
  4. Terrain only if you want the showpiece. It's the most striking view and the worst one to operate from, and it's the only one that needs a custom wgpu pipeline. If it lands, Tilted is a free preset on top of it.

// #[serde(default)] keeps existing prefs loading as today.
pub enum Scene     { Split, Terrain, Tilted }
pub enum SpecMode  { Trace, Ridges, Persistence }
pub enum WfMode    { Flat, Relief }

pub struct View {
    // …existing fields…
    pub scene: Scene,          // Split
    pub spectrum: SpecMode,    // Trace
    pub waterfall: WfMode,     // Flat
    pub ridge_secs: f32,       // 6.0, slider 2–10 s
    pub persist_secs: f32,     // 1.0, half-life slider
    pub relief: f32,           // 1.0, slider 0.25–2
    pub terrain_height: f32,   // 0.42
}
